# Westside Deployment Guide

This repo has:
- Frontend: React + Vite (root project)
- Backend: Express + Discord bot (`backend`)

The frontend is configured for Netlify, and the backend is configured for Render (always-on process).

## Local development

Frontend:

```bash
npm install
npm run dev
```

Backend:

```bash
cd backend
npm install
npm run dev
```

## Deploy frontend to Netlify

The repository already includes:
- `netlify.toml`
- `public/_redirects` (SPA fallback)

In Netlify, set:
- Build command: `npm run build`
- Publish directory: `dist`
- Base directory: repo root

Set environment variables in Netlify:
- `VITE_BACKEND_BASE_URL=https://<your-backend-domain>`
- `VITE_DISCORD_AUTH_URL=https://<your-backend-domain>/auth/discord/login`

## Deploy backend to Render

The repository already includes `render.yaml`, which creates:
- A web service named `westside-backend`
- A Postgres database named `westside-db`

Steps:
1. Push this repo to GitHub.
2. In Render, open **Blueprints** → **New Blueprint Instance** → pick this repo and branch.
3. On the review screen, fill every value Render prompts for (these map to `sync: false` entries in `render.yaml`). `SESSION_SECRET` is auto-generated by the Blueprint (`generateValue: true`).
4. Create the Blueprint. Wait until **Postgres** shows **Available**, then the **web** service should finish **Deploy live**.
5. Copy the web service URL (for example, `https://westside-backend.onrender.com`).

Use `backend/.env.example` as a template for required backend variables.

### Render troubleshooting (when deploy shows “failed”)

1. Open the **westside-backend** service → **Logs** (not just “Events”). Scroll to the **first red error**; that line is what matters.
2. **Build failed (`npm ci`)**  
   - Message like `package-lock.json` out of sync: run `npm install` inside `backend/`, commit the updated `backend/package-lock.json`, push, redeploy.
3. **Build failed (`npm run build` / `tsc`)**  
   - Fix TypeScript errors locally (`cd backend && npm run build`), commit, push.
4. **Deploy failed / health check failed**  
   - Do **not** set `PORT` manually on Render for this app. Render sets `PORT` for you; the server must listen on that value (the repo’s Blueprint no longer overrides it).
   - Confirm **Environment** has `DATABASE_URL` populated (Blueprint wires it from `westside-db`). If `PROFILE_DB_MODE=postgres` but `DATABASE_URL` is empty, the app will crash on startup.
   - Confirm every required secret exists: `DISCORD_CLIENT_ID`, `DISCORD_CLIENT_SECRET`, `DISCORD_REDIRECT_URI`, `SESSION_SECRET`, `APPROVAL_ADMIN_DISCORD_ID`, etc. A missing variable usually throws `Missing required environment variable: ...` in logs.
5. **`DISCORD_REDIRECT_URI` must exactly match** the URL in the Discord Developer Portal (scheme, host, path, no trailing slash mismatch).

### Manual web service (no Blueprint)

If you prefer not to use a Blueprint:

- **Root Directory**: `backend`
- **Build Command**: `npm ci && npm run build`
- **Start Command**: `npm run start`
- **Health Check Path**: `/health`
- Add the same environment variables as in `render.yaml` (create a Render Postgres instance and set `DATABASE_URL` from its **Internal Database URL** or connection string).

## Required backend variables

At minimum, set:
- `FRONTEND_ORIGIN` to your Netlify URL
- `FRONTEND_SUCCESS_URL` to `https://<netlify-url>/#/members`
- `SESSION_SECRET` (auto-generated by Blueprint, or set manually if you created the service without Blueprint)
- `DISCORD_CLIENT_ID`
- `DISCORD_CLIENT_SECRET`
- `DISCORD_REDIRECT_URI` to `https://<backend-url>/auth/discord/callback`
- `DISCORD_BOT_TOKEN`
- `DISCORD_GUILD_ID`
- `APPROVAL_ADMIN_DISCORD_ID`
- `DATABASE_URL` (auto-wired by Blueprint from Render Postgres)

## Discord OAuth callback update

In the Discord developer portal for your app, add the production callback URL:

`https://<backend-url>/auth/discord/callback`

## Verify after deploy

1. Open backend health endpoint:
   - `https://<backend-url>/health`
2. Open Netlify frontend and verify member/auth flows.
3. Ensure CORS is correct (`FRONTEND_ORIGIN` matches frontend domain).
